# 正解例の形式検査

基準は `docs/decisions.md` と `docs/hard-rules.md` の「正解例の形式」、特に「形式の規約（v1.3）」です。

Node.js 24 でリポジトリのルートから実行します。

```sh
npm ci
npm run golden:check
npm run typecheck
npm test
```

`golden:check` は `golden/` を再帰的に探索し、Schemaファイルそのものを除く全 `.json` を検査します。draft・undecided も対象です。0件、JSON構文不正、重複キー、Schema不適合、意味の検査の失敗は終了コード1になります。各エラーにファイル名を表示します。

Schemaは未知キーを全階層で拒否します。数量の5項目は一括で省略でき、省略した値を0で補いません。承認済み状態では承認者・承認日時・期待結果が必要です。undecided は expected 自体を省略します。draft の承認欄は未承認を表す null を使用します。

意味の検査は差分計算、暦日の実在、勤務パターンの区間と被覆、割当参照、ID重複です。日時の実在確認はホストのタイムゾーンに依存しません。この検査は期待結果を自動生成・書換えせず、Hardルールの適否を計算するValidatorでもありません。draft の期待結果は正式な照合結果として扱いません。

## 最初の下書き

- `H10/H10-rest-1199min-fail.json`: 文書掲載のJSONをそのまま保存。12/8 06:00〜12/9 01:59は1,199分。最小1,200分に1分不足するため期待結果FAIL、diff = 1199 − 1200 = −1。
- `H10/H10-rest-1200min-pass.json`: 入力の変更はLATEの開始時刻01:59→02:00だけ。12/8 06:00〜翌日12/9 02:00は20時間＝1,200分。期待結果PASS。両例ともdraft・承認欄null。

## 未決・今回の対応範囲

文書に具体的なJSONキーや値がない部分は推測で追加していません。この初版は掲載H10例を表す範囲のSchemaです。

- 判定不能理由のキー名・理由コード・記録種類の値は未決です。`INDETERMINATE` 時の理由1件以上という条件は定義済みですが、理由の要素形式を未定義（`items: false`）としているため、現時点では非空の `indeterminate` を持つ例は受け付けません。FAILに判定不能理由を併記する例も、形式確定後にSchema拡張が必要です。
- `forbidden_sequences` の非空要素、成人以外の `age_class` のJSON値・適用期間、資格、需要、希望休、固定、引継ぎ、対象外条件の確認状態等の具体的なJSON形式は未決です。現段階では掲載例の空の禁止並びと成人だけを受け付け、未定義キーは拒否します。H01〜H19の全入力形式を完成したという意味ではありません。
- 期間境界の引継ぎ元ID・引継ぎ内容の形式は未決です。`group_id` は文字列として受け付けますが、引継ぎ照合は未実装です。
- CIの保護対象変更検知と本人確認の運用は未決です。このワークフローは内容検査を実行します。承認状態をJSONに記入しても本人承認の証明にはならず、文書どおり監査・本人によるマージが別途必要です。

依頼文のPASS例の「翌々日」は、元の例の勤務開始日を維持すると「翌日」です。導出には具体的な日付で記載しています。
