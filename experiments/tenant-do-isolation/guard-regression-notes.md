# guard 回帰テストの保存と再現

この追加は、PR #3 で採用された guard を繰り返し検査できるようにするものです。guard 本体、reporter、既存の unit 14 件・runtime 8 件、期待結果、package scripts、CI、golden、正本は変更しません。

## 実行

Node **v24.22.1** を使います。追加の依存導入や Cloudflare 接続は不要です。リポジトリのルートから:

```sh
node --test experiments/tenant-do-isolation/test/guard-regression.test.mjs
```

実験ディレクトリからは:

```sh
node --test test/guard-regression.test.mjs
```

テストは作業ディレクトリではなく自身の位置を基準に `scripts/` を読みます。入力元の差替え用環境変数はありません。guard と reporter は import 前に SHA-256 を検査し、PR #3 head `f6302d33d436ae6ab1d32fbf397db06821f9ed05` / main `d569571b753dd30b462a1ac3dacc1a6f79391499` の採用バイトと違えば停止します。将来の実装修正時に pin を変えるだけで承認・監査を省略してよい、という意味ではありません。

## 68 件の範囲

- 正常な最低件数 14 / 8 と追加 15 件の受入れ。
- 不正な最低件数、起動失敗、signal、非ゼロ終了、人工的な timeout 結果の拒否。
- 空・途中切れ・不正・重複・余分な出力、非正規 JSON、重複キー、未知形式・フィールド・数値の拒否。
- 件数不足、不一致、failed / cancelled / skipped / todo の非ゼロ値の拒否。
- 整数検査だけを狙う追加4件。`suites` を負数・小数・安全整数上限超過・文字列にし、他の件数は整合させます。負数ケースでも `topLevel=1` とすることで、件数不足や上下限比較だけで拒否される検体にしません。
- reporter がファイルごとの summary を累計へ二重加算せず、最後の累計だけを出すこと。
- 実 reporter + 合成 Node テストで、正常、skip、todo、失敗、不正ソース、宣言なし、14件を宣言してからの `process.exit(0)`、stdout 混入を確認。早期終了ではプロセスの終了0と完了件数不足、および `Test counts rejected` を確認します。
- 変更していない CLI を隔離フォルダへコピーし、unit / runtime の正常系、引数不正、reporter / test 欠落を確認。

合成 fixture は OS の一時領域へ作り、各テスト終了時に自分が作ったフォルダだけを削除します。追加の子テストランナーには親ランナーの `NODE_TEST_CONTEXT` を引き継がせず、再帰実行の抑制による未実行を成功と取り違えないようにします。

## 採用・CI・監査の境界

この 68 件は、以前の一時的な人工検証 34 項目を復元したものではなく、後から作成した再現可能な回帰テストです。実 tenant unit 14 件 / workerd runtime 8 件の件数には加算しません。

現在の CI は固定された既存の 2 ファイルだけを実行するので、このファイルを追加しただけでは **68 件は CI で実行されません**。CI 接続はこの追加の範囲外です。CI が緑でも、この 68 件が GitHub 上で実行されたと報告してはいけません。「回帰テスト未収録・CI 未接続」という残件のうち、保存・手動再実行を可能にする部分だけを扱います。

120 秒の実タイムアウトはこの短い回帰スイートでは待たず、人工的な timeout 結果を検査します。別の隔離検証で約 120.28 秒・ETIMEDOUT・exit 1 を観測したことと、この 68 件の実行は区別します。

新規追加テストに対する独立監査・本人採用は別です。PR #3 の再監査上限を超えて追加監査するものではありません。このテストの成功を、製品認証・テナント分離の完成や本番公開の承認とは扱いません。

## 現在残す限界

初回監査の low 指摘である、外側の10秒 timeout後に孫プロセスが残る可能性は未修正です。フォルダの清掃とプロセスツリー全体の停止は別で、後者を保証しません。今回は実行管理の大きな書き換えを避け、数値検査と早期終了検体の補強に限定しました。既存READMEの古い状態説明も、この追加の2ファイルとは別の残件です。

すべての拒否ケースが各内部条件を単独で検査しているという意味ではありません。数値の4件と早期終了は拒否理由を絞りましたが、その他の既存ケースには一般的な `assert.throws` も残っています。
